Voxtype on KDE: direct typing with Klipper recovery

A small setup kit for packaged Voxtype 1.0.1 on KDE Plasma 6 (Wayland) with PipeWire. Press, talk, press again: the complete utterance is typed at the cursor. A default helper briefly publishes it to Klipper, then guardedly restores your previous supported plain-text clipboard.

Tested baseline: Debian 13 (trixie), amd64 x86-64-v3 · KDE Plasma 6 / Wayland / PipeWire · Voxtype 1.0.1 upstream .deb. Ubuntu/Kubuntu with compatible packages is untested.

1. What this kit is, and is not

This repository is a configuration recipe, small helper and operator runbook for packaged Voxtype 1.0.1. The installer manages three whole files: a preset, a visible KDE desktop entry, and a Python clipboard-history helper. It is not a Voxtype fork, replacement daemon or package manager. It never installs packages, downloads models, edits service units, switches the Voxtype binary or edits KDE's shortcut database by hand. Those remain deliberate operator actions (§7).

config/voxtype.toml             preset, including the default history hook
config/packages.sha256          pinned GitHub asset digest for the upstream .deb
desktop/voxtype-record-toggle.desktop   visible KDE shortcut entry (Meta+Space default)
scripts/clipboard_history.py    complete-dictation save/copy/restore hook
scripts/{install.py,doctor.py,record-sample.sh}   installer / checker / manual recorder
Makefile                        plan / install / doctor / test / check
docs/guide.html                 this guide; embeds docs/dictation-flow.svg

The design is final-on-stop transcription, direct typing plus best-effort Klipper recovery, and an explicit account of what can fail. There are no application-specific profiles, streaming fragments, separate transcript archives or Klipper database edits. The helper uses system Python's standard library and existing packaged commands; it needs no new Python package or service.

Enabled by default: a temporary, non-atomic clipboard replacement

The helper saves supported plain text A, publishes the complete dictation T, waits for Klipper capture, and guardedly restores A. Normally ordinary Paste returns A and Super+V offers T behind it. This is not atomic preservation or a history-only API: concurrent copies, failed restoration, unsupported offers and Klipper policy can prevent that outcome. Klipper may persist the dictation to disk. Read §5 before enabling the kit; remove [output.post_process] to opt out.

2. What Super+Space actually does

The chain, link by link:

  1. KDE Plasma catches the key. The visible Voxtype Record Toggle application (Utility category) declares X-KDE-Shortcuts=Meta+Space for its launch action. Desktop-cache discovery is not a binding guarantee: confirm it in §7.4. Voxtype's kernel-level hotkey is disabled ([hotkey] enabled = false); KDE needs no input-group access for the shortcut itself.
  2. The entry runs voxtype record toggle. The packaged one-shot CLI signals the running daemon (SIGUSR1 to start, SIGUSR2 to stop) and exits. The daemon reads its configuration at startup; this kit uses no per-recording profiles.
  3. PipeWire / ALSA supply the current default microphone. Voxtype records 16 kHz mono into RAM, with a waveform via GTK4 layer-shell and desktop notifications. Nothing is typed before stop. The duration and memory limits are in §4.
  4. The second press stops capture. Local Whisper transcribes the whole utterance once. The English base.en baseline is already loaded (on_demand_loading = false); choose your own model, language and CPU/GPU backend.
  5. The default history hook runs. The helper uses wl-clipboard to save supported plain text, publish the finished dictation and guardedly restore the saved text. qdbus6 observes exact capture in Klipper. It handles only this dictation, not earlier context, and always passes its original input through (§5).
  6. The text is typed at the focused cursor. The first available typing driver wins: eitype, dotool, then ydotool (driver details: §7.1). The latter two use uinput. No paste key, select-all or extra submission key is sent; recognised line breaks can still generate Enter events. Typing failures do not trigger a second clipboard-output fallback, but the preceding history hook has its own documented failure risks.

4. The recording ceiling, honestly

Voxtype 1.0.1 stops every recording at max_duration_secs — a hard wall-clock safety timer, not silence detection; pauses do not reset it. There is no unlimited mode in this release, so this kit sets the largest finite value the configuration accepts:

ValueWhat Voxtype 1.0.1 does with it
0Stops almost immediately (the daemon checks the timer on a fast poll). Zero is not an "unlimited" sentinel — it makes things worse, not better.
60The upstream default: dictations longer than a minute are cut off and transcribed early.
3600The largest value voxtype config set accepts; the TOML file itself accepts more.
4294967295The largest u32, accepted by direct TOML edit — ≈136 years: effectively "I stop it myself", while staying a real, finite bound the code handles cleanly. This is the preset's value. (Sources: §9.)

Three consequences, stated plainly:

  • RAM is the real limit. A recording is one growing in-memory buffer: 16 kHz mono float32 is 64,000 bytes/second, i.e. 3.84 MB/minute or ≈230 MB per hour, before allocator slack and the copies made at stop/transcription time. A forgotten days-long recording will exhaust memory long before 136 years elapse. The huge ceiling removes a nuisance, not a law of physics.
  • Manual stop is a privacy contract. With no practical automatic cutoff, the microphone stays open until you press Super+Space again. After stopping, check that the waveform disappears or run voxtype status; do not rely on notification popups your session may have suppressed.
  • No silence-based rescue either. Voxtype's VAD option (off here) only rejects silence-only recordings after the fact; it never ended a recording mid-pause. If you want a shorter safety net, pick an explicit finite value such as 3600 and edit the TOML directly.

5. Default clipboard recovery: operation, limits and opt-out

5.1 The normal path: save A, publish T, restore A

The save/copy/restore helper is installed and enabled by default. Let A be your current supported plain-text CLIPBOARD and T the complete finished dictation. With ordinary Klipper history settings and enough capacity, the intended result is CLIPBOARD = A and history [A, T]: ordinary Paste still inserts A, and Super+V can recover T. Delivery remains mode = "type", not paste; no clipboard driver or clipboard failure fallback is added.

  1. Preflight, lock and snapshot. Require the packaged commands, explicit local Wayland/session-bus endpoints, a private user-owned runtime directory, readable Klipper history and a nonblocking private lock. A busy lock skips rather than queues another dictation. Read actual clipboard offers with wl-paste --list-types and bytes with wl-paste --no-newline; never use history-top text as the backup. Recheck the offers and bytes before writing.
  2. Publish all of T, then await exact capture. Send the whole dictation through wl-copy's stdin. Poll qdbus6 org.kde.klipper /klipper getClipboardHistoryItem 0 for the exact UTF-8 text plus qdbus6's single framing LF; do not strip the item's own newlines or use a guessed capture delay. An already-retained duplicate is acceptable.
  3. Guardedly restore and verify. After any attempted publication, including a failed or timed-out command, cleanup checks the real clipboard. Restore A only while it still matches our T; a detected newer copy C wins. Check restored bytes, wait for the final clipboard text to become history head, and confirm T is still retained using bounded history probes. A failed restoration or retention check is not reported as confirmed recovery.
  4. Continue normal typing. The helper writes its original stdin bytes unchanged to stdout, even on a skip or failure. Nonzero status makes Voxtype fall back to its original transcript. That is text-processing fallback, not clipboard-output fallback; history trouble must not take direct typing away.

5.2 The hook and its deliberately small boundary

The installer puts scripts/clipboard_history.py at ${XDG_DATA_HOME:-$HOME/.local/share}/voxtype-setup/clipboard_history.py, mode 0600, before installing the configuration. Python reads it; it is not executable. The preset uses this exact upstream post-processing interface:

[output.post_process]
command = 'exec /usr/bin/python3 "${XDG_DATA_HOME:-$HOME/.local/share}/voxtype-setup/clipboard_history.py"'
timeout_ms = 5000
trim = false
fallback_on_empty = true

The helper uses only the Python standard library, wl-copy, wl-paste and qdbus6. No Python D-Bus binding, native client, extra service or database access is introduced. The ordinary background wl-copy provider serves the selection; it is not another managed daemon. A small empty lock file may remain under XDG_RUNTIME_DIR.

T matches this preset's dispatched text, not an arbitrary custom pipeline. Voxtype 1.0.1 still removes trailing LF characters with trim = false, then normalizes eight curly quote/prime characters to ASCII before output. The helper mirrors those steps for the history copy while leaving its stdout byte-exact; interior line breaks, spaces and other Unicode remain. Custom formatters or append_text choices are outside this baseline. The helper ignores prior dictation context and puts no transcript in command arguments, files, logs or diagnostics; its failure message is content-free.

5.3 Supported snapshots — and explicit skips

Only readable UTF-8, genuinely plain-text offers are supported: text/plain, text/plain;charset=utf-8 and conventional UTF8_STRING/TEXT/STRING aliases. The old text's bytes, including trailing newlines, are restored, but the original set of alias formats may change. This is not a promise to preserve every MIME representation or application-specific meaning.

  • Rich or unknown offers are skipped before writing: HTML, images, URI lists, cut/copy metadata and other unsupported formats are not silently flattened to text.
  • No offer is not empty text. Absent/nil or unreadable selections are skipped. A valid supported text offer containing zero bytes is distinct and can be restored.
  • Size and session failures skip before publication. Text/snapshots over 1,048,575 bytes, invalid UTF-8, missing commands, unavailable session/history access or an unsafe/busy lock do not authorize a clipboard replacement. Oversized dictations still pass through to typing.

5.4 Races, timing, history policy and privacy

Best effort is not compare-and-swap

A user copy can occur between the last check and a restore. The helper prefers a detected newer C, but cannot eliminate that gap or promise that ordinary Paste always returns A. During the temporary replacement, another application can read T; failed cleanup, a crash or SIGKILL can leave T current. Choose the no-hook opt-out below if that trade-off is unacceptable.

  • Bounded work, not hard real-time. Commands have approximately 250 ms deadlines; normal work has a 1.5 s budget, followed by a separate 1.5 s cleanup reserve, inside the hook's outer 5 s timeout. Normal-error and ordinary termination paths attempt guarded cleanup. Scheduling, process startup and forced termination prevent a hard millisecond latency or crash-recovery guarantee; this step can delay typing.
  • PRIMARY needs selection synchronization off. The helper requests only CLIPBOARD. Klipper or another manager can mirror that into PRIMARY when synchronization is enabled, so no unconditional PRIMARY-preservation claim is made.
  • Klipper policy still governs retention. Capacity one cannot retain distinct A and T. Duplicates reuse entries; new copies can reorder or evict them, and bounded checks may fail to confirm retention. History may be disabled, ignored or cleared. Klipper may save dictations to disk under its own persistence policy: recovery is not a private in-memory archive.
  • No supported atomic history-only API exists in Plasma 6.3.6. Its D-Bus slots provide getters, clear/save and setClipboardContents; that setter writes both CLIPBOARD and PRIMARY. Internal history insertion is not exported (§9). This kit instead uses the explicit temporary CLIPBOARD round trip, never SQLite edits or a second transcript archive.

5.5 Opt out, or diagnose without touching the clipboard

For pure direct typing, remove the entire [output.post_process] table from config/voxtype.toml, review make plan, reapply with explicit replacement permission, and restart Voxtype only while idle. Leave the typing-only driver list, mode = "type" and fallback_to_clipboard = false intact. The installed helper can remain unused; output then needs no clipboard tools. qdbus6 still serves the separate KDE shortcut check.

make doctor never runs the helper or reads clipboard/history. With the known hook selected it checks its command/settings, command availability and installed helper metadata (regular file, user-owned, mode 0600, safe parent), not the helper's contents or actual operation. A custom hook receives qualified diagnostics, not a blanket safety promise. Manual acceptance is in §8.

5.6 Historical comparison: built-in paste-and-restore is not this helper

Voxtype 1.0.1's built-in paste mode is a separate implementation, not the default here. Source review found wl-paste without --no-newline (which can add a newline to restored text), a single-MIME snapshot, unguarded restoration over concurrent copies, and failure paths that can strand the dictation (§9). The kit's helper avoids those specific choices, but still accepts the underlying non-atomic trade-off.

Earlier native experiments explored multi-representation restoration and ownership notifications. They are historical comparisons, not extra installed components or proof of lossless preservation: the shipped helper deliberately skips rich offers. Observed short replacement intervals do not establish an exact global exposure window or a guaranteed two-millisecond round trip.

6. Microphone, on-screen display, notifications

The microphone follows the system default. With device = "default", each recording opens the input currently selected through KDE / PipeWire's ALSA route. Plug in a headset and make it default in KDE's Sound settings; the next take uses it without a daemon restart. PipeWire/WirePlumber owns fallback when a device disappears and may select a different available input. A change mid-recording can cause a gap — start a fresh take. voxtype info devices lists names if you deliberately want to pin one. Neither installer nor doctor opens a microphone.

The OSD is best-effort about placement. The preset shows a 400×48 px waveform strip, horizontally centred at 85% of the screen height, via the GTK4 layer-shell frontend. Layer-shell lets the compositor choose the output, so on multi-monitor setups the strip may appear on a different display than you expect — there is no pinned-monitor option in this release. Notifications via libnotify may be suppressed by focus/do-not-disturb modes or per-application notification settings even though Voxtype sends them; the waveform OSD and voxtype status are the dependable indicators.

7. Fresh installation

Prerequisites: KDE Plasma 6 on Wayland with PipeWire, packaged Voxtype 1.0.1, a configured typing driver (eitype, dotool or ydotool), GTK4 layer-shell for the OSD, and wl-copy/wl-paste/qdbus6 for the default recovery hook. qdbus6 also checks shortcut ownership. The kit uses Bash, Python 3.11+ and Make; git/wget fetch the checkout/release. Everything below is an explicit operator action: the installer never invokes package managers, sudo, downloads, group changes, service commands or binary switches.

Debian 13 amd64 is the tested baseline. The prebuilt DEB needs an x86-64-v3 (AVX2) CPU. Ubuntu/Kubuntu with compatible Plasma 6 packages is untested; check library/package availability and service names rather than assuming Debian's packaging. An existing working Voxtype installation needs no purge, backend switch, model re-download or group change merely to apply these three assets (§7.3).

7.1 Debian 13 (trixie) example: apt first, then the two manual downloads

Everything apt can provide comes first — this kit's helpers, the OSD library, audio tools and entry validation (desktop-file-utils is optional). ydotool 1.0.4 lives in the official trixie-backports repository, so enable it per the Debian Backports instructions before the second command — the kit never adds repositories:

sudo apt install git make python3 wget \
    libgtk4-layer-shell0 wl-clipboard libnotify-bin pipewire-alsa \
    alsa-utils qdbus-qt6 libkf6service-bin desktop-file-utils
sudo apt install -t trixie-backports ydotool

Only two pieces are manual downloads, because apt does not carry them: the upstream Voxtype release and the Whisper weights. Fetch the DEB into this checkout's ignored tmp/, verify it against the pinned digest, then let apt install the local file — dependency resolution still comes from apt. The weights are a separate explicit voxtype setup step, deliberately without --activate:

# Run from this checkout's root; downloads stay under ignored tmp/.
mkdir -p tmp/packages
wget -O tmp/packages/voxtype_1.0.1-1_amd64.deb \
    https://github.com/peteonrails/voxtype/releases/download/v1.0.1/voxtype_1.0.1-1_amd64.deb
sha256sum --check config/packages.sha256
sudo apt install ./tmp/packages/voxtype_1.0.1-1_amd64.deb
voxtype setup --download --model base.en

The pinned checksum is GitHub's published release-asset digest, not an independent publisher signature; upstream's SHA256SUMS.txt does not cover the DEB, so it is not used as a false verification step.

About the typing drivers: the preset tries eitype (libei/portal; each invocation briefly registers with the remote-desktop portal), then dotool (uinput, keyboard-layout aware), then ydotool (uinput, needs its daemon, sends raw US keycodes — potentially wrong on non-US layouts). See the upstream driver reference for eitype/dotool. wtype is absent because KWin Wayland does not implement its virtual-keyboard protocol. Unavailable drivers are skipped; make doctor reports availability but never invokes one.

CPU or GPU is your call. CPU inference works with the package as installed. On supported hardware you may opt into a GPU backend with the upstream interactive sudo voxtype setup gpu --enable, which manages the /usr/bin/voxtype variant symlink; voxtype info variants shows the choices and voxtype info accel reports what is active. The kit never switches binaries and assumes no particular GPU vendor.

The input group is a privacy decision — never a silent one

Upstream suggests sudo usermod -aG input "$USER". Know what that grants: write access to /dev/uinput — which Debian's ydotool user unit needs for injection, as does dotool — and read access to every keyboard event on the system under /dev/input, which Voxtype's modifier-release guard separately uses. The Super+Space shortcut itself does not need the group, because KDE owns the key. It remains your call, made with both eyes open; neither this kit nor any script in it will ever add you to a group. If you accept, join the group yourself, then log out and back in fully before enabling the services. If you decline, ydotool's packaged unit cannot be promised to work — consider eitype, or a deliberately configured uinput permission arrangement for dotool/ydotool. Dotool is not a permission-free escape hatch; follow the chosen driver's upstream requirements. Either way, never work around the decision with world-writable devices or sockets.

7.2 Services: vendor units, explicit commands, idle check first

After applying the preset in §7.3, use the packaged service units; this kit ships none (/usr/lib/systemd/user/voxtype.service, and the ydotool unit your distribution ships — its packaging varies by distro; the names below are Debian's):

systemctl --user enable --now ydotool.service voxtype.service
voxtype status                            # confirm: idle, model loaded
# After ANY config change (the daemon reads config at startup only),
# restart only while idle, so you never kill a recording:
voxtype status                            # must show idle
systemctl --user restart voxtype.service

7.3 Apply, replace or undo the three assets

Clone the kit if needed. Run make check on the stock checkout before editing model/configuration choices: its baseline tests intentionally assert the supplied defaults. No live clipboard, microphone, service or user configuration is touched by those tests.

git clone https://github.com/dnouri/voxtype-setup.git
cd voxtype-setup
make check
# Optional: edit config/voxtype.toml for your model, language or other settings.
make plan       # read-only whole-file diff; the installer defaults to dry-run

Already running Voxtype? Keep the installed packages, model weights, backend and permissions. Match the preset's model/language to your existing choices if necessary: the installer preserves model files and binary selection, not the contents of your old configuration. Review all three planned files, then:

voxtype status                           # must be idle
make install INSTALL_FLAGS='--replace --refresh-desktop'
systemctl --user restart voxtype.service # explicit; reloads startup configuration

For a fresh install, use make install INSTALL_FLAGS='--refresh-desktop' after reviewing the plan, then start the packaged services (§7.2). --replace is necessary only for differing existing files. A no-op means identical files/modes, not a verified live setup.

The installer rejects relative XDG paths and symlink paths. Safe existing read/write bits are retained for config/desktop files; the helper is always 0600. These are whole-file replacements, not a merge. All preflight checks and required backups precede writes, and the helper is written before any new configuration that references it. The three-file operation is not a transaction: an interrupted/failed apply can leave a partial installation, which must be reviewed before retrying.

make install explicitly supplies --apply. Replacements require --replace; KDE cache refresh runs kbuildsycoca6 only with --refresh-desktop. A shortcut collision prevents applying. Unknown ownership also prevents it unless, after manual review, you explicitly use --skip-shortcut-check; that flag never forces a binding. A free Meta+Space is acceptable for install, but must be assigned afterwards (§7.4).

Private backups have numbered names, not destination names

The printed BACKUP: directory is under ${XDG_STATE_HOME:-$HOME/.local/state}/voxtype-setup/backups/. Its NN-basename files contain only originals actually replaced, numbered in replacement order; indices are not fixed asset identifiers. Restore each to its destination from the reviewed plan, removing the numeric prefix rather than installing that prefix as a filename. Do not assume all three assets have a backup.

Before undoing a running setup, check it is idle. Restore any required helper before a configuration that calls it; refresh the cache after restoring a desktop entry, then explicitly restart Voxtype while idle. Review permissions as well as contents: backup files are private 0600 copies. There is no automatic rollback or uninstaller.

For removal, stop Voxtype and remove its KDE shortcut before deleting the three managed assets. Do not delete the config and restart into unfamiliar upstream defaults. If only disabling recovery, remove the hook table and reload instead (§5.5). Packages, backend selection and downloaded models remain separate. Never restart KWin to discover a shortcut.

make doctor     # passive installed-setup checks; never runs the history hook
make test       # fake HOME/XDG/desktop commands only
make check      # offline tests plus Python/Bash syntax checks

7.4 Confirm the Super+Space shortcut, once, by hand

The entry installs as a visible application named Voxtype Record Toggle (category Utility; the file keeps its name voxtype-record-toggle.desktop and runs voxtype record toggle). It only declares Meta+Space as the default for its launch action: refreshing the desktop cache with kbuildsycoca6 (what --refresh-desktop runs, and only when asked) lets KDE discover the hint — it does not guarantee the key is assigned. Confirm it once:

  1. Open System Settings → Keyboard → Shortcuts and search for Voxtype Record Toggle.
  2. If it is missing, choose Add New → Application… and pick the installed entry. Because the entry declares a command shortcut, it can appear under Commands rather than with the ordinary applications. Select its action and assign Meta+Space — keep the Default, or choose Custom and press Super+Space — then Apply. The doctor checks this exact combination; another one will be reported as unassigned.
  3. Do not use Add New → Command or Script: that registers a different desktop ID, and the doctor will report the collision. Never restart KWin to pick the entry up.

From then on make doctor treats an unassigned Meta+Space as an error, just like one owned by another component; the installer is satisfied with a free key and only stops on a real collision or undeterminable ownership. Neither tool can certify the actual microphone, typing focus, keyboard layout, or device/socket permissions — the manual test in §8 is the real check.

8. Verify it yourself

Automated checks inspect files and prerequisites, not actual dictation. Doctor reads TOML on disk and the installed desktop entry, checks the selected known hook and helper metadata, and warns about VOXTYPE_* overrides without showing values. It never imports/executes the installed helper, reads clipboard/history, records or types. It cannot certify the configuration already loaded by a running daemon, microphone selection, focus, layout, device/socket permissions or successful recovery. CI uses temporary HOME/XDG and fake commands, not a real session. No automated result substitutes for this deliberately manual acceptance test:

  1. Use synthetic, disposable content. With enough Klipper capacity, copy ordinary plain text A; avoid a rich application offer for this first test. If checking PRIMARY separately, disable Klipper's selection synchronization first. Focus a disposable editor, press Super+Space, speak a sentence and press again. Expect the complete result T at the cursor, with no extra submission key; recognised line breaks can still generate Enter events.
  2. Paste: the normal successful outcome is exactly A, including any trailing newlines. That verifies the final supported text, not an untouched clipboard: the hook temporarily published T. Open Super+V and check that the complete T remains in history, normally behind A. Rich/absent offers, disabled history, insufficient capacity or failures can skip recovery; direct typing should still work. A detected newer copy should be preferred, but no manual check abolishes the race in §5.
  3. When relying on long takes, deliberately verify a recording beyond 60 seconds yourself. Stop explicitly and check that the waveform disappears or voxtype status returns idle. Nothing in this kit records automatically.

Optional: your own voice, your own vocabulary. scripts/record-sample.sh requires an interactive terminal and explicit Enter before recording a local sample; installer, doctor and tests never record. Audio stays in ignored tmp/samples/ and is never committed. The upstream transcribe command prints file-only results to the terminal, bypassing live typing and the history hook; it changes no configuration:

voxtype --config config/voxtype.toml transcribe "tmp/samples/<dir>/sample.wav"
voxtype --initial-prompt "Project names: Voxtype, Klipper, Plasma." \
    --config config/voxtype.toml transcribe "tmp/samples/<dir>/sample.wav"

An initial_prompt is a short spelling/casing hint for Whisper — a nudge, not a guarantee. Keep it to a few terms you dictate daily (project names, tool names) and that you have approved; long or unverified word lists bias output for the worse.

  • Klipper's exported D-Bus slots (getters/clear/save/setClipboardContents only): klipper.h and klipper.cpp (setClipboardContents writes both PRIMARY and CLIPBOARD); history insertion is internal: historymodel.h, historymodel.cpp (all plasma-workspace v6.3.6).
  • Whisper model weights: whisper.cpp ggml model cards; enabling backports: Debian Backports instructions.
